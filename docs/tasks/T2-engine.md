# T2-engine — the analysis engine

## Objective

`analyze(session)` in `src/domain` does what the frozen contract says: stages 2–5 over every
compaction of a Session with pre-labeled items, stage 1 first when it carries none. The sixteen
expected tests move out of `src/domain/pending/` and pass. A parity test proves the engine
equals the reference script (`scripts/autopsy-check.py --report-json`) on the three committed
fixtures. Pure TypeScript, no packages, no runtime loading (architecture rules R1–R4).

## Dependencies

- Contract frozen at v1 (`docs/contracts/FROZEN` present). Nothing else.
- Runs in parallel with T3-ui-shell and T6-story-view; nothing in this lane waits on them.

## Lane rules

This lane runs in parallel with T3-ui-shell and T6-story-view. Nobody changes what a contract
term means. If this lane thinks the contract is wrong, it writes the issue in
`docs/CONTRACT-ISSUES.md` and keeps going: no edit to the frozen files, no refreeze inside the
lane. Ownership is disjoint by folder; a change this lane wants outside its list is not made,
it is written under "Requests" at the end of this file for the owning lane.

## Files not to touch

`src/fixtures/**`, `docs/specs/**`, `README.md`.

## Acceptance criteria

1. `src/domain/index.ts` exports `analyze`; `src/domain` imports nothing outside itself
   (architecture test green).
2. The four expected tests pass from their new location; `src/domain/pending/` does not exist;
   `npm run test:pending` and `vitest.pending.config.ts` are gone; `vite.config.ts` no longer
   excludes anything under `src/domain`.
3. `src/specs/parity.test.ts` deep-equals `analyze(fixture).reports[0]` to the committed
   reference JSON for each of the three fixtures (score compared at four decimals); the JSON is
   regenerated by one documented command and committed.
4. Extraction parity: `analyze` on each fixture with `items` stripped re-derives the same four
   items, ids, entities, anchors, and origins.
5. Every listed sentence in `docs/specs/algorithm-v1.md` (stage 4 "Listed cases") and every
   negative case in `docs/specs/testing-strategy.md` has a unit test in `src/domain`.
6. Multi-boundary: a synthetic Session with two compactions yields two Reports, items assigned
   by timestamp region; a unit test covers it.
7. `npm run check` green; `npm run build` green.

## Tests

`npm run check` (architecture, fixtures, frozen contract, expected reports, parity, domain
units). No Python at test time: the reference output is committed JSON.

## Out of scope

Anything under `src/ui`; the default-demo predicate wiring (T4-autopsy); the reference script's
CLI; new fixtures; subagent transcripts; microcompact boundaries.

## Parity reference

`src/specs/parity/<id>.report.json` is the output of one command per fixture, committed:

    python3 scripts/autopsy-check.py --fixture src/fixtures/<id>.json --report-json > src/specs/parity/<id>.report.json

`src/specs/parity.test.ts` deep-equals `analyze(fixture).reports[0]` to it (scores at four
decimals) and re-derives the items with `items` stripped.

## Findings (2026-09-16, engine lane)

- The reference builds `CLASS_RES` as a dict over `ENT_RES`, so for a `path` class anchor it
  keeps only the second path alternative (`(src|scripts|docs|config|logs)/…`), not the contract's
  full `PATTERNS.path`. The engine uses the contract pattern. No fixture carries a path class
  anchor, so the parity test cannot expose it; the reference is left as is and this is logged
  for the backlog (a class-anchor case would settle it).
- Regions with more than one boundary are half-open windows: before compaction `i` is
  `ts >= compactions[i-1].ts` and `ts < compactions[i].ts`; after is `ts >= compactions[i].ts`
  and `ts < compactions[i+1].ts`. A message at exactly a boundary's ts is after that boundary
  (review fix, 2026-09-16; the contract's "greater" for after is aligned in the v2 refreeze).
  The reference handles the first boundary only; `src/domain/analyze.test.ts` covers two
  boundaries and the equal-timestamp edge.
